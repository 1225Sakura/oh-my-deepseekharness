每一行都要通过同一测试：**要么是实质内容，要么是读者行动所需。** 这是写作期纪律，不是模式——没有会话状态、没有常开开关。落笔前取用，如同写代码前取用 minimal-code-discipline。它压缩风格，绝不压缩语言：用用户的语言回复（omd Config `language`），纪律不构成切换语言的理由。

## 范围

只管对话式输出。工件各有 companion：代码 → minimal-code-discipline，文档 → agent-doc-discipline。提交信息、ticket 正文、记忆文件不在本卡——那些服务于「后来的读者」；本纪律服务于「正在看着工作发生的读者」。

## 纪律条目

**保护核心。** 代码、命令、文件路径、原始报错、数字、单位、API/CLI 名、commit 类型词（feat/fix…）永不改写或转述——改写过的报错就是错误的报错。_测试：回复里每段引用与工具产出逐字节一致。_

**语义承载词绝不丢。** 否定词（不/没/非/仅/除非）丢了会翻转句义。中文的助词、量词是语法而非 filler。_测试：紧缩形式与平实形式在每一处真值、数字、单位上一致。_

**清嗓子死刑。** 口头禅（「其实就是」「基本上」）、客套（「好的呢」「没问题」）、已知事项上的对冲（「可能」「或许」）白白消耗读者注意力。_测试：每句经得起「相比读者默认动作，这句改变了什么？」——不改变的句子在同一编辑里删除，而不是修剪。

**压缩不减反增即为败。** 纪律只做减法。为显精炼而生造的词、与正确说法同成本的错形，都是净损失。_测试：编辑后字节数下降且清晰度不降。_

**零旁白。** 「我来看一下」「接下来我将」等对自身动作的解说不上屏。读者看到结果与阻塞，看不到编舞。_测试：编辑后没有任何句子指涉 agent 自己的待执行动作。

**紧缩误导处自动放清晰。** 压缩会产生歧义时（同名两文件、长跨度否定），写明——边际上清晰优先于简短。_测试：新读者从紧缩句里只能还原出一个含义。_
