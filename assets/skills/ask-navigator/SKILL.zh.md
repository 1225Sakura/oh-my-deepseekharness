# ask-navigator（领航员）

ask-navigator 是**领航员**：它接过一项裹在雾里的工作——从这里到目的地的路还看不见——把它绘制成一张**决策票地图**，然后每会话推进一张前沿票，直到路线清晰。它产出**决策，永远不是交付物**：路清晰了就交接，不建造。

> **移植说明。** OMC 原版属于 Shipyard 家族（`drydock`、`launch`、`loft`、`harbor`），**未移植到 omd（二期或更晚）**。本文使用的替代方案，如实声明：
> - `drydock --check` 场地审计 → 跳过；场地未铺设（无 `CONTEXT.md`、无 `docs/adr/`）时领航员记一笔即继续。
> - `loft` 票型 → 领航员 spawn `omd-agent-executor` 建造能回答该问题的一次性 artifact。
> - `launch` 交接 → omd 无 launch；mission brief 交给 **autopilot**（或 team）作为交付模式。
> - `harbor` 入口 → 模糊请求直接作为松散想法进入本通道。
> - issue tracker（GitHub/GitLab）→ omd 零外部依赖：**local markdown 是默认地图之家**；仅当用户显式要求且有 `gh`/`glab` 可用时才用 tracker-backed 地图。

**角色契约。** 船长（人类）签署目的地（W1）与海图（W2）；领航员起草其余一切，**绝不回答属于船长的问题**——一场 agent 自问自答的拷问会，破坏的是角色而不只是流程。事实是领航员的职责；决策是船长的。

**雾测试。** 任一答案为否，工作即有雾：

1. **Q1**——目的地能用一句话陈述吗：这项工作要抵达的规格、决策或变更？
2. **Q2**——前三个决策此刻能精确陈述吗，即使它们都还无法回答？

两个都是 → 不需要地图；直接交付（autopilot/team）。任一为否 → 先绘图。`ask-navigator` 也可直接触达：带松散想法、带残余问题调用，或不带参数续推打开的地图。

## 地图之家

默认地图之家是 **local markdown**：`.omd/wayfinder/<map-slug>/map.md` 加 `decisions/NN-<slug>.md`，每票一文件，按依赖序编号。本地模式无并发认领保证：约定单驾驶员，在地图的 Notes 里声明一次。

当且仅当用户显式要求 tracker-backed 地图且有 CLI 可用（`gh`/`glab`，经 `pwsh` 检查）：一个带 `navigator:map` 标签的 map issue，每票一个子 issue，用原生 blocking/sub-issue 关系。此时地图长在人类本就在看的地方。

无论哪种，地图是**索引，不是仓库**：一个决策只住在一个地方——它的票。地图用一行话 gist 每个决议并链接；绝不复述细节。

## 文档语言

地图与票的正文跟随仓库文档语言：有 `CONTEXT.md` 时读其 frontmatter 的 `documentLanguage`；场地未铺设时在绘图（W2）阶段问一次语言问题，并把敲定的标签记入地图的 Notes。路径、标签、`navigator:map` 标签、票型名（`research`、`loft`、`grilling`、`task`）、`HITL`/`AFK`、`blockedBy` 是稳定 token，在任何语言中逐字节不变。

## 绘图（chart the map）

带松散想法（或残余问题）调用。绘图是一个会话的工作；它手工解决不了任何票。

1. **场地检查，发现延后。** OMC 的 `drydock --check` 审计未移植——改为：场地未铺设（无 `CONTEXT.md`、无 `docs/adr/`）时在地图 Notes 的 `Deferred sediment` 下记一笔即继续；绝不因场地阻塞绘图。
2. **W1——命名目的地。** 加载 `deep-interview` skill，敲定这张地图要找的路通向什么：规格、决策或变更。目的地定死范围，所以最先敲定。**W1 是船长签署：呈现目的地陈述并拿到显式确认。** 如果船长连访谈帮助也给不出目的地，那不是错误——呈现排序后的最佳候选，让船长挑一个作为绘图方向，或把这项工作停泊。
3. **绘制前沿。** 再用 `deep-interview` 拷问，**广度优先**：在整个空间上扇开，而不是在单条线上深挖，浮出悬而未决的决策与现在就能迈出的第一步。**若此举没有发现雾**——通往目的地的路已清晰且一趟会话走得完——不需要地图：停下并建议直接交付（autopilot/team）。
4. **W2——签署海图。** 呈现拟议地图：目的地、带类型与阻塞边的初始票、雾的草图。**W2 是船长签署**：这里的粒度错了会浪费之后每个会话。迭代到签署为止。
5. **创建地图与票。** 本地模式：写 `map.md`，每票写一个 `decisions/NN-<slug>.md`；票号落定后第二趟再接阻塞边（`blockedBy`）。还不够锋利、无法成票的一切留在 **Not yet specified**。
6. **发射 research 子代理。** 为刚创建的每张 `research` 票 spawn 一个后台 `subagent` 并行解决（见票型），把发现留在票能链接的地方。
7. **停下**，给出会话收尾指针：地图路径、前沿上还有几张票、"下个会话运行 `ask-navigator` 推进下一个决策"。

## 推进地图（work through the map）

带地图（路径）调用，或不带参数（拾起 `.omd/wayfinder/` 下打开的地图）。票可选：不指定时取前沿上的下一张票，而不是让船长挑。

1. **加载地图**：只看低分辨率视图，绝不一次读所有票正文。需要时再放大某张票的全文。
2. **先认领再动工**：**先**在票文件里写 `Claimed-by`（tracker 模式：指派给船长或留评论），让并发会话跳过它。打开且未认领的票就是未认领。
3. **按票型解决**（见票型）。需要时放大；解决需要船长输入时加载 `deep-interview` skill。
4. **记录决议**：把答案写为票的 Resolution 段，关闭票（completed；判定超出目的地的票以 not planned 关闭），并在地图的 **Decisions so far** 追加一行——`[<票标题>](路径): <一行 gist>`。
5. **推进前沿**：把答案已使其可成票的雾毕业（从 **Not yet specified** 移除、创建新票、接边）；若答案显示某票超出目的地，**关闭它**并在 **Out of scope** 留一行；更新或删除被该决策作废的票。
6. **沉淀**（见 Sediment）。
7. **一张票即停。** 每会话一个决议是节奏——那是上下文窗口预算，不是政策。会话收尾指针点名刚解决了什么、前沿现在有什么。

## 票型

每张票是 **HITL**（与船长共同推进，船长自己发言）或 **AFK**（领航员独立驱动）。HITL 票只能通过实时交流解决；agent 绝不代替船长那一方作答。

| 类型 | 模式 | 解决方式 | 何时用 |
|---|---|---|---|
| `research` | AFK | 后台 `subagent`：对着一手来源（官方文档、源码、规格）调查，把带引用的 Markdown 留在 `docs/research/<ticket-slug>.md`（或仓库既有笔记约定），从票链接过去 | 决策卡在超出当前工作目录的知识上 |
| `loft` | HITL | spawn `omd-agent-executor` 建造一次性 artifact 回答票的问题——可运行外壳里的纯逻辑模块，或一条路由后的结构性不同 UI 变体；船长反应，答案折进决议，artifact 留在 `loft/<name>` 分支（OMC 的专用 `loft` skill 未移植；纪律相同） | 问题精确但 prose 定不了——需要被看见、被点开，而不是被描述 |
| `grilling` | HITL | 加载 `deep-interview` skill；每轮由船长定夺 | 对话即决议——默认情形 |
| `task` | HITL 或 AFK | 领航员能独立做就独立做；否则交给船长一份精确 checklist | 解锁决策的手工活（注册服务、开通权限、搬动数据以看清形状）——它凭解锁决策赢得位置，不靠交付目的地 |

答案绝不属于票正文；它在决议时记录。解决过程中产出的资产从票链接，不粘贴进去。

## 地图正文

```markdown
## Destination

<走到这张地图尽头的样子：这项工作要抵达的规格、决策或变更。一两行；每个会话选票前先对准它。>

## Notes

<领域；每个会话应参考的 skill；长期偏好；场地未铺设的注意事项；敲定的 documentLanguage 标签；本地模式的单驾驶员约定>

## Decisions so far

<!-- 索引：每张已关闭票一行，足以判断相关性，细节顺链接放大到票内 -->

- [<已关闭票标题>](路径): <答案的一行 gist>

## Not yet specified

<!-- 在范围内但尚无法成票的雾；随前沿推进而毕业 -->

## Out of scope

<!-- 判定超出目的地的工作；已关闭，永不毕业 -->
```

**雾还是票？** 检验标准是"此刻能否精确陈述问题"，而不是"此刻能否回答"。问题已经锋利就成票，即使被阻塞。无法那么锋利地表述就进 Not-yet-specified——不要把雾预先切成票大小的块；一片雾可能毕业成几张票，也可能一张都没有。**Out of scope** 是划范围的动作，不是路线上的一步：把它放进去的是范围而非锋利度，只有目的地重绘它才会回来。

## 沉淀（Sediment）

决议落定的那一刻就沉进纸面轨迹：

- 决议敲定或磨利的术语 → `CONTEXT.md` 术语表（一条：定义、边界、已解决的歧义）
- 通过 ADR 检验的决策（难以逆转、缺了上下文会意外、真正的权衡）→ `docs/adr/NNNN-<slug>.md`
- 业务规则或背景事实 → `docs/business/`（每个业务问题一篇）

场地未铺设时，**延后，不跳过**：把每笔待落地在地图 Notes 的 `Deferred sediment` 标题下记一行，让之后的交付运行确切知道先落地什么。

## 出口——交接，不建造

没有打开的票且 **Not yet specified** 为空时，地图完成。然后：

1. 把 **Decisions so far** 坍缩成一份 **mission brief**：目标、范围边界、non-goals——现在写得出来，因为路已清晰。写到 `.omd/wayfinder/<map-slug>/brief.md`，让交接传递指针而非内容。
2. 建议："路已清晰。用 `autopilot`（或 `team`）携带 `.omd/wayfinder/<map-slug>/brief.md` 的 brief 交付。"（OMC 的 `/launch` 未移植；autopilot/team 是 omd 的交付面。）地图留作这项工作的航行日志。

## 范围与 non-goals

- 无守护进程、无模式、无常驻行为、无运行时状态机：地图就是 `.omd/wayfinder/` 下的普通仓库文件。
- 绝不动 team 生命周期、任务状态或模式状态；绝不发布交付票——建造票属于交付模式，领航员绝不把雾预切成建造票。
- 除记录外绝不执行决策。唯一例外是 `task` 票，它只做解锁决策所需的事。
- 地图的 Decisions-so-far 是索引；一个决策只住在一个地方——它的票。

## 完成定义

绘图会话以船长签署的地图与已发射的 research 票告终。推进会话以恰好一个已记录决议、前沿已推进、会话收尾指针已发出告终。工作在路已清晰、mission brief 已交船长并推荐了交付模式时告终——领航员代船长做的每个决策，都能用一个指向记录位置的指针回答。

## 状态契约

ask-navigator **不持模式状态**——刻意如此：没有 `state_write`/`state_clear`，`.omd/state/` 下没有任何内容。`.omd/wayfinder/<map-slug>/` 下的地图文件就是全部持久状态；"恢复"就是读那张打开的地图。这与 OMC 原版的 no-daemon/no-mode 契约一致。
