# agent-doc-discipline（agent 文档纪律）

在创建或编辑任何 agent 要读来行动的文档时应用本纪律：agent 向文档（`AGENTS.md`、`CLAUDE.md`、`CONTEXT.md`、`docs/standards/`）、spec、ticket、技能文件（`.dsh/skills/`）。文档必须通过的测试：**一个全新的 agent 会话只靠阅读它就能行动。**

说明：在 OMC 里这套纪律在船厂流程中是强制的（drydock 种子生成、launch C5 sediment pass）；drydock/launch 已移植到 omd（见同名技能），本纪律在其种子生成与 C5 沉淀 pass 中同样为强制，其余 agent 向文档编辑按需使用——但任何对 agent 向文档的编辑都应该经得起这些规则。同样，OMC 的 `.omc/skills/` 习得技能面映射为 dsh 技能根（项目 `.dsh/skills/`、用户 `~/.dsh/skills/`）。

## 何时不用

只写给人类看的文档：`docs/business/` 叙事、ADR 决策故事、人类 onboarding 的 README。零成本处仍可遵循这些规则，但它们不受本纪律约束。

## 纪律

**为没有聊天记录的读者写。** 文档必须自描述：不许依赖"如前所述"、上一次会话、只存在于某人脑中的知识。_测试：_ 一个全新的 agent 会话只靠阅读就能按文档行动。

**每条规则可检查且带 why。** 不写"保持整洁"——写可观测条件和理由。_测试：_ agent 仅凭文本就能判定 pass/fail，且 why 就写在规则旁边。

**一个含义，一个家。** 每条规则或定义只有一个权威位置；重复就是等待发生的 drift。_测试：_ 改一个行为只需改一处。

**绝不复述环境自己已经说出的东西。** package scripts、目录布局、`--help` 输出是 lookup，不是文档——抄下来的 lookup 会过期。只记录靠看看不出来的东西：未成文的约定、选择背后的理由、坑。_测试：_ 每一行都经得起"这能在别处查到吗？"

**步骤在前，参考在后，低频材料藏在指针后面。** 要做什么、按什么顺序，放最顶上；按需查阅的规则放下面；低频材料推到指针后面，指针的措辞要点名哪些分支该去取它。_测试：_ 下一个动作在第一屏内找得到。

**每一步都以完成判据收尾。** done 必须能和 not-done 区分开——模糊的边界招致过早完成。_测试：_ 对每一步，"我怎么知道这步完成了？"在文中有答案。

**写正向指令。** 陈述目标行为；禁令只留给硬护栏，且必须搭配正向目标。_测试：_ 文档里每条禁令都点名了替代做法。

**写的时候顺手刮藤壶。** 文档里有陈旧或冗余材料，就在同一次编辑中删掉；没有就只加必需材料，不发明删除。模型默认就会遵守的句子白付负载——整句删掉。_测试：_ 重读的每一行都经得起"相对默认行为，它改变了什么？"，且编辑中发现的陈旧冗余已清除。

## 验证

报告文档改动完成之前确认：

- 全新会话不向人类提任何问题就能按它行动
- 每条规则可检查且带 why；没有规则在复述 lookup
- 含义只住在一个地方；指针点名了它的触发分支
- 编辑中发现的陈旧冗余已删除，且无关的有效内容完好保留

## 状态契约

agent-doc-discipline **不持模式状态**。它是写作期纪律：不做 `state_write`/`state_clear`，不在 `.omd/` 下创建文件。它的交付物就是被编辑的文档本身。
