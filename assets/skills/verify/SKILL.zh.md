# verify（验证）

需要确信某个功能、修复或重构真的有效时使用本技能。

## 目标

把模糊的"应该能跑"变成具体证据。

## 流程

1. 明确必须证明的确切行为。
2. 优先跑现有测试。
3. 覆盖缺失时，跑可用的最窄直接验证命令。
4. 直接自动化不够时，描述手动验证步骤并收集具体可观测证据。
5. 只报告实际验证过的东西。

## 验证顺序

1. 现有测试
2. Typecheck / build
3. 窄直接命令检查
4. 手动或交互验证

## 规则

- 没有证据不说完成。
- 检查失败就把失败写清楚——引用原始输出。
- 不存在现实可行的验证路径时，明说，不装。
- 要简洁的证据摘要，不要噪音日志。
- 作为独立门禁时与作者上下文分离——委派时用 `subagent` spawn `omd-agent-verifier`（绝不在 authoring 上下文自我批准）。

## 输出

- 验证了什么
- 跑了哪些命令/测试
- 通过了什么
- 什么失败了或仍未验证

## 状态契约

verify **不持模式状态**。在外层模式内（autopilot 验证门、ralph 独立评审层、team-verify 阶段）持久化由外层模式的状态契约管辖；verify 的交付物就是它的证据报告——作为子代理即最后一条消息，在主会话即验证摘要——verify 自身不在 `.omd/` 下创建任何文件。
