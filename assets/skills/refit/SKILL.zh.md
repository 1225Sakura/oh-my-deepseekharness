Refit 盘点 agent 工作所处的环境——不是它产出的代码（那归 review/verify），也不是单次运行的教训。每种工作都会留下摩擦：反复绊倒 ralph 循环的同一检查、等信号而 stalls 的 autopilot、决定性输出没被留存的调试会话。omd 对这一切都有仪表。Refit 读仪表，把记录在案的摩擦转成环境变更，让下一次运行从更好的船坞出发。

## 证据先行

从仪表出发，而不是从清单出发。提问之前先读：

- `trace_summary` / `trace_list`（MCP）——回合在哪里 stalls、重复、无谓扇出
- `events_read`（MCP）——派发审计轨迹（route/fallback 1:1）
- `.omd/hb.log` 与 `.omd/state/` 下会话状态——stale 队员、被吞掉的失败
- notepad（工作区）——近期会话累积的问题
- 仓库自有检查面（`package.json` scripts、CI workflow）——提议任何新检查前先读，因为「已存在但没接线/静默失效的检查」本身就是发现，而不是重发明

发现从数据里长出来。空盘点是合法结果，如实陈述；编造发现与跳过盘点同罪。

## 四个修复承载面

每条发现指名拥有其修复的承载面。不属于任何面的发现，显式拒绝并说明理由。

1. **确定性检查**——失败是机械性的（固定语法形态、禁用 API、import 形态、文件位置规则）。修复=lint 规则、门禁测试或 CI job——取既有护栏里最便宜的载体。默认「建检查」优于「写规矩」。
2. **转向面**——失败是护栏替代不了的判断（跨文件一致性、贴合周边风格）。修复落在 AGENTS.md / docs / omd wiki——导航指针优于长文。
3. **工具面**——摩擦来自工具本身（token 低效的 MCP 调用、缺自动化、检查慢到关键时刻跑不动）。修复落在 Config 键、`scripts/` 或插件工具面。
4. **信息面**——agent 需要一个够不到的信号（dev-server 日志、服务状态、远程只读访问）。修复=落盘日志、暴露状态、或写清访问路径。

## 审批门——refit 与 self-improve 的分界

self-improve 自治改码（锦标赛选择、无审批门）。**Refit 未经用户逐条批准绝不落地**：盘点产出发现表（发现/证据/承载面/建议修复），用户逐行批准，只有批准的行变成变更。一次未经批准就编辑的 refit，违反的是它唯一的硬规则。

## 分工表

| 需求 | 承载面 |
|---|---|
| 产出代码的质量发现 | review / verify |
| 自治代码改进 | self-improve（无审批门） |
| 知识沉淀 | remember / wiki |
| 环境摩擦 → 经批准的环境修复 | 本卡 |
