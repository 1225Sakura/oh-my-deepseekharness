为本次对话的真实走向构建一张紧凑、有证据的地图，让用户在切换会话或压缩后快速重定向。仅顾问摘要——绝不是规划器、执行器或用户任务清单的替代品。

## 模式

- 无参数：渲染完整地图；持久面可用时同步本 skill 持有的阶段记录。
- `short`：只报目标、当前阶段、需要用户的事项。只读。
- `reset`：只删除本 skill 持有的记录，确认删除内容；不渲染新地图。

## 工作流

1. 从本对话的用户消息与工具结果重建流程。仓库状态本身不构成「某阶段发生过」的证据。把原始目标与显式目标变更、转向、已完成产出、被放弃路径、等待用户的决策分开。
2. 历史支撑得够就给 4–8 个有意义的阶段；宁少勿凑。每阶段一个结果标记：
   - `✅` 已完成（附产出）
   - `▶` 当前未完阶段
   - `○` 已计划未开始
   - `✂` 已放弃（附原因）
   - `↪` 转向（旧方向 → 有证据的新方向）
3. 每阶段给一个紧凑证据指针——对话中出现过的真实路径或独特短引文。绝不编造链接；证据早于压缩点的重建标 `inferred`。
4. 全图至多 15 行：每阶段一行 + 目标行 + `Needs you`（未决决策；无则写 none）+ `Next`（仅当对话支持具体下一步时给出）。

## 持久化（omd 适配）

上游把持有阶段记在宿主 Task 工具；dsh 无该面。持久化改用 notepad 工作记忆区：

- 持有记录带精确标记 `session-flow: managed stage` 与 `[S<number>]` 主题前缀，写入工作记忆 notepad。
- 默认模式：将持有记录与地图对账（存续阶段号保持稳定；删除地图中已消失阶段的记录；补建缺失记录）。
- `reset`：只删除同时带 `[S<number>]` 前缀与标记的记录；确认删除。
- 带标记的记录是描述性历史，绝不是执行模式状态——不得用于武装或触发任何 omd 模式。
