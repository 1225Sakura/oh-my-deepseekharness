**图是承重结构，不是装饰。** 只有当散文迫使读者在脑中一次装下整个形状时才动用——然后选让读者「看见形状」的最小视图，而不是用句子重新拼装。一切都在会话里以文本块或 Mermaid 呈现；至多写一个工件文件。

## 词表——选一个视图，至多两个

- **伪代码**——去掉语言噪音的逻辑；把决策还原成分支形状。
- **调用树**——运行时控制流；深度显示谁拥有流程；在关键边上加注。
- **组件树**——UI/模块结构，内联标注重要边界。
- **文件树**——职责住在哪里；浅层，每目录一条注记。
- **Mermaid**——多方交互、数据流或状态迁移。
- **Diff**——周边结构已存在时变更的形状（按组件/布局/调用树/状态机整形）。
- **完整块**——省略会隐藏归属或顺序时，完整展示一次，可复制。

## 选择规则

让视觉匹配读者要回答的问题：谁拥有流程 → 调用树；谁和谁通信 → Mermaid；变了什么 → 按变更整形的 diff；东西住哪 → 文件树。两个视图打平时取更小的那个。绝不堆全部形式——一个视觉通常就够。

## 散文不够时

UI 布局、前后对比、或 Mermaid 装不下的稠密概念：写一个聚焦的 HTML 文件并渲染（omd 视觉工具链可截图验证；UI 变更用 visual-verdict 对照参考图评判）。然后停——一个工件、真实标注、真实数据。

## 反模式

- 复述相邻散文的装饰图。
- 三行调用树能答的偏画 Mermaid。
- 宽到看不清变更的 diff——diff 围绕变更整形，而不是围绕文件。
- 编造代码里没有的结构：视觉即证据，与 file:line 同级。
